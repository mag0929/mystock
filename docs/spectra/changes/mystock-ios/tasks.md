## 6. 已實現損益

- [x] 6.1 實作賣出紀錄與批次配對輸入（`Sale record with user-designated lot allocation`）：不提供預設配對，必須使用者逐批指定股數，支援跨多個批次；未分配完則拒絕儲存並回報剩餘未分配股數。驗證：單元測試涵蓋單批次配對 1000 股、跨批次 400／600 股配對共 1000 股、以及僅分配 900 股時被拒絕並回報 100 股未分配
- [x] 6.2 實作配對完整性檢查（`Allocation integrity constraints`）：配對股數總和須等於賣出股數、任一批次剩餘股數不得為負，違反時拒絕儲存並指出是哪一條；同一批次的多筆配對須合併後再檢查。驗證：單元測試涵蓋分配 1100 股／賣 1000 股被拒、對剩餘 500 股的批次分配 600 股被拒、以及對剩餘 500 股的批次分兩筆 400 + 300 被合併判為 700 而拒絕
- [x] 6.3 實作每筆配對的已實現損益計算（`Realized profit per allocated lot`）：賣價 × 配對股數 − 批次每股成本 × 配對股數 − 該筆賣出的費用與交易稅分攤，賣出的已實現損益等於各配對之和。驗證：單元測試涵蓋單一配對 1000 股賣 130 對應成本 90 的批次，以及「allocation choice changes the reported split」範例兩組結果（配對 90 批次得 +40000／剩餘成本 150000；配對 150 批次得 -20000／剩餘成本 90000）
- [x] 6.4 實作總損益守恆（`Total profit conservation`）：任一標的的所有已實現損益加總必須等於賣出總收入減總取得成本（含費用與稅），不受配對方式影響。此機制對應 design.md 的「三種成本算法的比較」。驗證：單元測試以 1000@150 + 1000@90 賣 1000@130，對兩種配對方式皆斷言總額為 20000
- [x] 6.5 實作拒絕將賣出配對到配股批次（`Stock allocation lots are never allocated`），並回報該批次為配股批次不可配對。驗證：單元測試嘗試配對配股批次時被拒且錯誤訊息指明配股批次
- [ ] 6.6 實作已實現損益查詢區間（`Realized profit query periods`）：當日、當月、前三月、自訂區間，皆以賣出日期篩選，輸出已實現損益總額、筆數、扣除的手續費與稅。驗證：單元測試涵蓋當日 2 筆得 3000、2026-03-10 查前三月納入 1/10・2/15・3/05 三筆、自訂 2026-02-01 至 2026-02-28 僅納入 2/15、空區間回報 0 筆 0 額
- [ ] 6.7 實作依代號分組與逐筆檢視（`Realized profit by symbol and by sale`），每筆顯示賣出日期、代號、股數、賣價、所配對的批次與該筆已實現損益。驗證：單元測試查 2330 於 2026-03 區間得單一分組且總額等於兩筆之和，並排除其他代號
- [ ] 6.8 實作賣出手續費與稅額記錄（`Fee and tax handling on sales`）：手續費依設定費率、交易稅 0.3% 從已實現損益扣除，證交稅 0.4% 僅作為參考值記錄而不扣除；費率於賣出當時寫入，之後改設定不回溯。驗證：單元測試 1000 股賣 130 記錄手續費 185.25、交易稅 390、證交稅參考值 520，且費率由 0.1425% 改為 0.15% 後舊賣出仍用 0.1425% 計算
